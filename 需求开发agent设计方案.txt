Service Monitor Agent 需求与设计方案

一、项目目的
面向小型公司多台 Linux 服务器的日常运维场景，提供低部署成本的桌面监控工具。应用在本机运行，通过 SSH 采集服务器指标并读取项目日志，无需在被监控服务器安装 Agent。

核心目标：
1. 集中展示多台服务器的 CPU、内存和本地磁盘使用率，并对高占用及持续异常进行提醒。
2. 按项目管理日志文件，提供按需的日志对话分析和报告导出。
3. 加密保存 SSH 密码，严格校验服务器主机身份，降低凭据泄露和误连风险。
4. 使用 Go 与 Wails v2 构建跨平台桌面程序。

二、范围与边界
1. 当前定位是单机桌面监控工具，不是服务器端 Agent、完整 APM 平台或自动化运维平台。
2. 当前不包含进程管理、服务启停、远程任意命令执行、历史趋势分析和多用户权限系统。
3. 应用启动后必须由管理员解锁凭据才能开始采集，因此当前不支持无人值守的开机自动监控。
4. 日志分析依赖使用单位自行提供的兼容 OpenAI Chat Completions 接口；未配置模型时不生成模拟分析结果。

三、功能设计

1. 服务器与凭据管理
（1）支持配置多台服务器，基本信息包括服务器标识、名称、地址、SSH 端口和用户名。
（2）首次启动时创建加密凭据文件并设置至少 12 个字符的管理员口令；也可由管理员使用 vaulttool 命令行工具创建包含首台服务器的凭据文件。
（3）后续添加服务器时需再次输入管理员口令。每次重启应用后均需重新解锁，解锁前不开始采集。
（4）SSH 密码只保存在加密凭据文件中，不在界面、日志、分析报告或普通配置文件中显示或记录。
（5）凭据文件采用 Argon2id 从管理员口令派生密钥，再使用 AES-256-GCM 对 JSON 数据进行认证加密。管理员口令不写入文件，遗失后无法从加密文件恢复，应由公司另行妥善保管。
（6）严格使用当前系统用户的 ~/.ssh/known_hosts 校验 SSH 主机公钥。首次连接前通过可信渠道核对指纹；未知或发生变化的主机密钥必须导致连接失败，不提供静默跳过校验的方式。
（7）监控账号遵循最小权限原则，至少能够读取 /proc/stat、/proc/meminfo，执行 df -Pk -l，并读取已配置的日志文件。

2. 资源监控界面
（1）按服务器展示 CPU、内存和磁盘使用率，同时展示最近更新时间和采集状态。
（2）默认每 30 秒采样一次，采样周期可配置。
（3）CPU 使用率通过间隔 1 秒的两次 /proc/stat 采样计算。
（4）内存使用率依据 /proc/meminfo 中的 MemAvailable 计算，避免将可回收缓存直接视为已用内存。
（5）磁盘通过 df -Pk -l 获取本地挂载点数据，以最高占用率作为该服务器的磁盘告警判定值；界面应能区分不同挂载点，避免只显示汇总值而掩盖异常位置。
（6）采集失败时明确显示错误和离线/未知状态，不得将失败数据当作 0%，也不得用旧数据冒充最新数据。

3. 告警与消息通知
（1）CPU、内存和磁盘的默认高占用阈值为 80%；实际判定为“超过 80%”而非“达到 80%”。阈值可配置。
（2）阈值告警：单次有效采样超过阈值时触发。
（3）持续告警：相邻采样上升至少 20 个百分点且达到高占用条件，随后连续 5 分钟不低于阈值时触发。突增幅度和持续时间可配置。
（4）阈值告警与持续告警在界面和消息中应明确区分，避免同一现象被描述成含义不清的重复告警。
（5）飞书使用官方 AppID / AppSecret 与 WebSocket 长连接，接收 im.message.receive_v1 事件以发现 chat_id；实际文本告警通过官方 IM OpenAPI 发送。界面显示连接状态、错误与已发现会话。
（6）QQ 按 API v2 文档使用 AppID / AppSecret 获取 QQBot access token，通过 /v2/groups/{group_openid}/messages 或 /v2/users/{openid}/messages 发送群聊或 C2C 单聊。Gateway WebSocket 用于连接及发现目标会话。保存时只校验机器人凭据，不强制校验目标类型或 OpenID；实际发送前再校验目标。OpenClaw 页面中的“灵魂”属于独立智能运行时，需另行启动 OpenClaw Gateway，不与本程序的告警连接混为一谈。
（7）AppID 和目标会话保存在普通配置；飞书、QQ AppSecret 与模型 API 密钥使用随机数据密钥加密保存在 private-data.enc，数据密钥由管理员口令加密保存在 private-key.enc。解锁后自动恢复；界面只显示配置状态，不回显或提供复制明文的功能，SQLite 中不写入密钥。旧版本未持久化的密钥须重新输入一次。
（8）告警状态保存在 alerts.json 中，记录发送结果，避免应用重启后重复发送已经成功送达的同一告警。
（9）发送失败和采集失败都应在界面可见。同一告警在单个渠道失败 3 次后停止本次投递并持久化失败次数，新告警重新计数。当前版本只确认 OpenAPI 接受投递，不等同于用户已阅读。

4. 项目日志配置
（1）项目配置包括项目名称、所属服务器、项目文件目录和日志文件绝对路径。
（2）日志路径必须指向具体文件，而不是整个目录，以减少无关文件读取和敏感数据外发。
（3）项目目录用于标识项目位置；日志分析只读取已明确配置的日志文件，不递归扫描项目目录。

5. 日志对话分析
（1）由用户主动发起分析，不在后台持续上传日志。
（2）单次分析最多读取目标日志末尾 256 KiB，并仅将其中最后 32 KiB 发送给模型接口，避免无限制读取和传输。
（3）模型配置包含平台、OpenAI 兼容 BaseURL、API Key 和模型下拉框。填入密钥后调用 GET {BaseURL}/models 获取当前账号可用模型；分析使用 POST {BaseURL}/chat/completions。端点必须为 HTTPS；仅允许本机地址使用 HTTP。模型 API 密钥加密保存在私有数据文件，重启后解锁即可恢复，不写入普通配置。
（4）使用单位必须确认模型服务的数据政策允许接收相关日志。日志可能包含个人信息、令牌或业务数据，配置分析前应进行数据合规审查；当前版本不承诺自动脱敏。
（5）界面展示模型返回的分析内容，并支持围绕已读取的日志上下文继续对话。成功的问答、来源、时间和日志摘录加密保存，解锁后可按项目回看与导出，并用最近 6 轮问答继续对话。最多保留最新 100 条；私有数据文件超过 8 MiB 时淘汰最早记录。旧版本仅存内存的记录无法恢复。不得将模型推测表述为已经验证的事实。
（6）未配置模型、接口不可用或请求失败时，应显示真实错误，不生成虚假的分析结果。

6. 分析报告导出
（1）支持将分析结果导出为 Markdown 文件。
（2）报告包含最近 8 KiB 的日志摘录，以便复核分析依据。
（3）导出前明确提示报告可能包含敏感日志；报告文件由使用者负责保管，不自动上传或外发。

四、界面设计
1. 服务器总览：展示多台服务器、三项资源指标、采集状态和异常信息。
2. 服务器设置：维护连接信息，提供凭据解锁和新增服务器所需的管理员口令输入。
3. 告警设置：维护采样周期、阈值、突增幅度、持续时间及通知渠道。
4. 项目管理：维护项目与所属服务器、项目目录、日志文件路径的对应关系。
5. 日志分析：选择项目、发起分析、查看对话和导出 Markdown 报告。
6. 对密码、API 密钥等敏感输入使用掩码控件；错误提示应帮助定位问题，但不得回显秘密值。

五、架构与数据流
1. 前端：Wails 桌面界面，负责配置、状态展示、分析对话和导出交互。
2. Go 后端：划分为凭据管理、SSH 连接、指标采集、告警判定、消息通知、日志读取、模型调用和报告导出等模块。
3. 配置与状态：项目、告警及其他设置保存在当前操作系统用户配置目录下的 ServiceMonitorAgent 目录中；SSH 加密凭据文件为 credentials.enc，私有数据密钥封套为 private-key.enc，密钥和分析记录密文为 private-data.enc，告警状态为 alerts.json，其他数据使用数据库或状态文件保存。
4. 监控数据流：定时采样 → SSH 执行只读采集 → 指标解析 → 界面更新与告警判定 → 通知发送 → 保存告警状态。
5. 日志分析流：用户选择项目 → SSH 限量读取日志 → 截取允许发送的末尾内容 → 调用已配置模型 → 展示对话结果 → 用户主动导出。

六、安全与可靠性要求
1. 加密文件主要防御静态文件泄露；本机拥有系统级控制权限的人仍可能在应用运行时提取解密后的 SSH 密码，不能宣称可以防御已失陷的本机。
2. 不使用硬编码主密钥，不以可逆编码冒充加密，不在版本库中提交真实密码、Webhook、API 密钥或日志报告。
3. SSH 采集和日志读取应具有明确的错误处理，单个服务器失败不应阻断其他服务器的状态展示。
4. 所有外部输入，包括服务器地址、文件路径和模型端点，都应经过校验；日志内容作为不可信数据处理，不直接执行为命令。
5. 指标和告警以有效采样为依据，不能用缺失数据参与计算或掩盖故障。
6. 大数据量控制通过限量读取实现；导出和模型请求均应由用户明确触发。

七、验收标准
1. 添加至少两台测试服务器后，能够分别展示 CPU、内存和各本地磁盘挂载点使用率，采集失败有明确状态且不会显示为 0%。
2. 使用可控指标数据验证：超过 80% 触发阈值告警；相邻采样突增至少 20 个百分点且超过阈值，并持续 5 分钟不低于阈值时触发持续告警。
3. 验证飞书官方应用鉴权、WebSocket 连接、会话发现与 IM OpenAPI 投递；验证 QQ API v2 鉴权、群/C2C 投递和旧版 WebSocket 兼容连接，并展示官方下线限制及真实失败原因。
4. 重启后未解锁时不能采集；错误口令不能解密；凭据文件和运行日志中不出现 SSH 明文密码。
5. 未知或变化的 SSH 主机密钥会被拒绝，合法 known_hosts 记录可以正常连接。
6. 能配置项目及日志文件，读取大小符合限制；模型未配置或调用失败时有真实提示，成功时可继续对话并导出 Markdown 报告。
7. 报告包含约定的日志摘录，且不包含 SSH 密码、模型 API 密钥、AppSecret 或其他机器人秘密。
8. 真实服务器、飞书、QQ 和模型链路需在相应测试环境完成端到端验证，不能以单元测试替代外部集成验证。

八、后续可选改进（不属于当前版本验收范围）
1. 增加通知重试间隔与退避、恢复通知，完善告警生命周期。
2. 在日志发送模型和导出报告前增加可配置的敏感信息脱敏，并提供外发内容预览。
3. 增加历史指标持久化与趋势图，评估磁盘、内存和查询性能成本。
4. 支持 SSH 密钥认证及操作系统安全凭据存储，减少长期使用密码的需求。
5. 如确需无人值守监控，应单独设计受限服务模式、凭据解锁方案和审计机制，不应简单取消启动解锁要求。
